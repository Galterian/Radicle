chaosD6 · Dimensions — decentralized architecture

A tactical tile-and-card RPG whose rulebook is versioned and voted on in git, whose live sessions are published as Doors on Radicle, and whose rounds are agreed on by the players themselves over libp2p, GunDB and a public Nostr bus. No host. No server. No central authority. Generated from the repository state on 2026-10-22.

Seven layers, bottom to top structure

Each layer is independently replaceable. The contract between them is the versioned JSON in data/: the engine, the Door files and the envelopes all follow shapes declared there.

A · Living rulebook

Every rule, card, class, creature and even the P2P protocol itself is a VersionedEntry with weighted versions.

  • concept · stats · elements · 26 rules · battle system · 10 actions · 66 effects · 14 skills · 33 classes · 12 characters · 29 creatures · 41 terrain items · 9 modes · 6 contradictions
  • Runtime contract: sync_protocol, hashgraph_events, dimension_session, governance
  • bundle.py packs everything into dimensions-bundle.json; editor.html is the living-rulebook browser

B · Governance

The git-fork metagame. Balance is proposed as a new version object on a proposals/* branch and voted with evt_vote.

  • Vote weight scales with proven use: 0.01·(1+log2(1+uses))·(1+0.1·dims), cap 0.10
  • Accept ≥ 0.6 weight, quorum 7, rebalance drift ≤ 15 %
  • Hard forks live in forks/* and may merge back as one proposal
  • not automated yet

C · Doors on Radicle

Branch ActiveDimensions/<Name>; every peer writes dimension.json and its own doors/<peer>.json into its own namespace.

  • Push every 60 s (paper: 1 h with lottery pusher)
  • Door newer than 3 min = player is live
  • Reader: rad sync --fetch + git for-each-ref refs/namespaces/*
  • Logs print public explorer URLs on rosa.radicle.network

D · Live mesh

One envelope, three carriers. gossipsub where peers can dial each other, Gun for presence and map blocks, Nostr for the path that is always open.

  • Envelope: type · turn · round · action_index · self_parent · other_parent · payload · state · _hash
  • Relays that pass the burst test: primal, snort, nostr.net, bitcoiner.social
  • Signatures are stubs; keys ephemeral per process

E · Round engine

Lives in game/peer.mjs, one process per entity. Fixed 6 s rounds, 3 rounds per turn, commit → reveal → deterministic resolve.

  • Silent peer = Empty Posture; laggards jump to the max clock
  • Each peer applies only its own tile and life, then publishes a state hash
  • Standoff keeps ticking so late joiners can resume

F · Growing map

js/map.js: grow-only set of hex blocks. Players reveal a disc of radius 10 near the frontier; blocks ride Gun, evt_map_extend and the Door.

  • Terrain from seedForDimension(dim_id), no exchange needed
  • Idempotent by block id, so order and transport never matter
  • uncommitted work

G · Client & launcher

The browser is a thin view over one peer's WebSocket. The launcher spawns peers, lists Doors and places joiners.

  • Keys 1–5 queue a slot, 8 Empty, Space lock, right-click discard / journey
  • A* journeys resumed every planning phase
  • join.mjs gives the same powers on the CLI

The round engine time

A fixed 6-second cadence with two short handshake windows that close early as soon as every expected member has answered. Three rounds make a turn; the turn boundary refills hands.

Anatomy of a Door doors/<peer>.json · v2

A Door is what one peer knows from where it stands, plus how to reach it. Doors from peers that met on the map overlap and agree. The Door is both the discovery record and the bootstrap for every transport.

How a Door is used

  • Discovery. The launcher lists every ActiveDimensions/* ref in every namespace, groups Doors by dimension, and marks a Door live if pushed within 3 minutes.
  • Placement. Joiners union all Doors' map blocks, then pick a free hex next to the anchor Door (nearby) or more than 2 tiles from every living member (random).
  • Bootstrap. Live Doors supply Nostr relays, libp2p multiaddrs and Gun URLs for the new peer's environment.
  • Clock. The joiner listens on the bus, adopts the most advanced clock and sits out the current action.
  • Namespaces. One file per peer in the peer's own namespace: pushes never conflict, so the branch merge is additive, exactly what sync_radicle_push.merge_policy asks for.

Map growth without a world server js/map.js · uncommitted

The world is a grow-only set of hex blocks. A block is tiny and idempotent, so it can be sent on every channel at once and received in any order.

Rules evolve in git governance.json

Balance is not patched by a designer. A change is a new version object with weight 0, voted up by people who demonstrably play with the thing being changed, guarded by a rebalance script, and released weekly.
