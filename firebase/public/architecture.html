Architecture · as of 2026-11-23

chaosD6 — Dimensions

chaosD6 is a fully peer-to-peer tactical card RPG on an endless hex map: every player runs the same deterministic engine and publishes a state hash, so there is no game server, no lobby and no host. The rulebook is versioned data that players propose and vote on, and Radicle (peer-to-peer git) is the shared memory for Dimensions, definitions, votes and team profiles.

Explore live Dimensions Rules (read-only) Android APK Code on Radicle

The rule of the design: every peer resolves every action itself and publishes a state hash. Peers that disagree log a STATE DIVERGENCE; a peer that cannot run the exact same definitions publishes no hash (it abstains) instead of guessing.

Version gates — definitions by reference

Built-ins travel by name, so two peers agree only if they run the same bundled definitions. Every snapshot carries a pin; once per action each peer compares the pins of the units in its view with its own.

Pin of a unit in my view…
✓same as mine→ resolve and publish my state hash
!no pin, slim record only→ unknown: skipped until its full snapshot arrives

Workflows

Six flows that tie the pieces together: a game action · joining from this web app · publishing a definition · proposing a data change · team profiles · seeds and desktop nodes.

Workflow · one game action

A paper round is 3 actions; every action all players play one card simultaneously. Every peer runs every step itself. Rules: battle system · actions · sync protocol.

Workflow · join a Dimension from this web app

A Dimension is one live session; its Doors (one per peer) are on the ActiveDimensions/<name> branch of chaosD6-Dimensions.

  1. 1

    Open /explore

    Active dimensions lists dimensions/<name> from Firestore; ✓LIVE = a Door seen in the last 3 min.

    firebase/public/app.js
  2. 2

    Pick a Dimension

    /dimensions/<name> shows its commits and the live Doors, plus a git clone --branch ActiveDimensions/<name> line for desktops.

    dimensions/<name>/doors/<nid>
  3. 3

    Tap “join”

    Next to a Door or commit: chaosd6://join?dim=<name>&rid=<RID>&peer=<id>&nid=<publisher>&commit=<sha>; &team=c joins as a third team.

    deep link
  4. 4

    The app opens

    The Android intent filter starts the app; the URI reaches EmbeddedPeer.gd (JOIN_URI) and DimensionLauncher.gd; a rid overrides the baked one.

    godot/scripts/
  5. 5

    Read the Doors

    The app fetches the Dimension's Doors through radicle-httpd and spawns next to the chosen unit, as its ally.

    game/mobile-entry.mjs
  6. 6

    Play + publish

    The phone's peer.mjs joins the mesh and pushes its own Door every ~60 s.

    → #round

No phone? Get the APK, or on a desktop run node game/join.mjs --dimension <name> --placement nearby or chaosd6-play --list.

Workflow · publish a new skill, effect or class

From the rules editor your node serves (http://127.0.0.1:7357/rules/, startup menu → Rules editor). The public rules site is always read-only; editing needs your team identity. Spec: EDITOR_SPEC.md rulings 1–3.

Rebalancing verdicts: ✓ok !nerf !boost ✕reject (refused)

Workflow · propose a change to a data entry

Rules, creatures, terrain, classes data … never change in place: a proposal is a new version. Governance lives in data/governance.json.

  1. 1

    Propose

    Signed in on your node, an entry → Propose a change → POST proposals with data (+ logic) and notes.

    editor/author.js
  2. 2

    New version

    version = active minor + 1, status: "proposal", weight: 0, origin: "player_vote", parent_version = active.

    writeDataFile + flock
  3. 3

    Rebalance verdict

    JsonLogic validation, then power score Δ: ✓accept if |Δ| ≤ 15 %, else counters → !accept_with_counters / ▲needs_rework; invalid → ✕blocked.

    tools/rebalance.mjs
  4. 4

    Counter-proposals

    Walks rebalance_links (depth ≤ 2) and drafts one version per linked entry (origin: rebalance_script), so the collection mean drifts ≤ 5 %.

    rebalance-<ts>.json
  5. 5

    Votes

    Signed votes; w = 0.01·(1+log2(1+uses))·(1+0.1·dims), ≤ 0.10 per peer; weight = clamp(Σ+ − Σ−, 0, 1). Tally every hour.

    governance_voting
  6. 6

    Canonical

    weight ≥ 0.6, ≥ 7 voters, age ≥ 1 day, within tolerance → ✓canonical; the old one is superseded. ≤ −0.3 or > 30 days → rejected.

    next session loads it
Player-made definitions get proposal votes too
Vote−6 … +6 per voter per def version; a minus vote needs a comment (≤ 500 chars); signed ed25519 by the device key
Authorno vote on your own definition (namespace, key or names match the branch's <who>)
Publishautomatic, debounced, OCI seed only, on votes/<voter> branches; failed → pending and retried
Effectbelow n = 10 none; n ≥ 10 and mean ≤ −3 → ▲review flag; a new def version starts empty

Source: game/effects-data/PROPOSAL_VOTES.md, game/proposal-votes.mjs, game/proposal-votes-publish.mjs.

Workflow · team profile sync

A team profile is one profile.json on refs/heads/teams/<Team> of chaosD6-Profiles; the seed is its only delegate. A player is an ed25519 device key with a z6Mk… id.

  1. 1

    Set a team

    Startup menu → team name. The device key lives in <profile dir>/radicle/identity.pem; it never leaves the device.

    game/profile-auth.mjs
  2. 2

    First claim wins

    The creating push lists the signer in owners; afterwards only an owner moves the branch, and owners never become empty.

    teams/<Team>
  3. 3

    Join request

    Another device pushes on its own profiles/<z6Mk…> branch; an owner accepts → the key is added to owners.

    profile-radicle.mjs
  4. 4

    Write (P2P first)

    The in-app radicle-node signs the commit into the device namespace; the seed's promoter moves the canonical branch.

    CHAOSD6_RADICLE_BRIDGE
  5. 5

    Write (fallback)

    git smart-HTTP to /profiles-push with X-Profile-Auth (ed25519 over ref, old, new oid + time, ±10 min); fast-forward only, ≤ 256 KB; then git push rad.

    infra/oci/profiles-push.mjs
  6. 6

    Read + merge

    radicle-httpd, depth 1, one ref; per-character merge, owners union; unsent saves wait in pending.json.

    game/profile-sync.mjs

The same team identity signs you into the rules editor (owner = logged in), signs proposal votes, and decides which nodes may serve your bots' LLM prompts (llm-route.mjs: only keys in your team's owners, direct libp2p only). Mirrors serve profiles read-only; writes always go to the delegate (OCI_NID).

Workflow · seeds and desktop nodes

A new seed — infra/oci/new-seed.sh

  1. 1

    Prepare

    Ubuntu 22.04/24.04 VM (OCI Ampere A1 works), TCP 22, 80, 443, 8776 open, an ssh key. --dry-run shows the plan.

    --host ubuntu@IP
  2. 2

    Provision

    seed-provision.sh over ssh: radicle-node, radicle-httpd, caddy (Let's Encrypt on <ip>.sslip.io), iptables.

    infra/oci/seed-provision.sh
  3. 3

    Policy

    peers: dynamic · seedingPolicy: block · rad seed --scope all for the 6 repos; upstream in node.connect.

    private seed
  4. 4

    Content

    /var/www/{rules,pack,downloads}: rules site (rules-site-build.mjs), asset pack, APK.

    --content all
  5. 5

    Options

    --with-llm / --llm-public (llm-setup.sh); --own-profiles only for a separate network.

    optional
  6. 6

    Wire players

    Prints NEW SEED: z6Mk…@<host>:8776 and seeder-<host>.json; it keeps in sync with the upstream over gossip.

    oci-seed-sync.sh

A desktop node — tools/setup-desktop.sh

  1. 1

    Tools

    apt packages, Node 22 (nvm), Radicle in ~/.radicle/bin.

    Linux · WSL2
  2. 2

    Identity

    rad auth only without a key; with a passphrase run it once per session.

    --alias NAME
  3. 3

    Node config

    The seed is the only peer and the preferred seed; seedingPolicy block; node restarted.

    --seed NID@HOST:8776
  4. 4

    Repos

    Clone the code, fetch Dimensions / Effects / Skills / Classes / Profiles from the seed only.

    --dir ~/chaosD6
  5. 5

    npm

    npm install from the public registry (ignores a private ~/.npmrc token).

    game/
  6. 6

    Play

    chaosd6-play → http://127.0.0.1:7357; set your team name in the startup menu.

    chaosd6-play --list
